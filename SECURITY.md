# Security Policy

## Supported Versions

NestExtended is released as a set of packages (`@nest-extended/core`, `@nest-extended/cli`,
`@nest-extended/decorators`, `@nest-extended/mongoose`, `@nest-extended/prisma`,
`@nest-extended/typeorm`) that share a single version number. Security fixes are only
published for the versions below.

| Version      | Supported          |
| ------------ | ------------------ |
| 1.5.x        | :white_check_mark: |
| 1.0.x        | :white_check_mark: |
| 0.0.2-beta.x | :x:                |
| < 0.0.2      | :x:                |

Only the latest minor release line receives security fixes. Releases within `1.x` are
backwards compatible, so if you are on `1.0.x` upgrade to the latest `1.5.x` before
reporting an issue. Pre-1.0 releases were beta previews and are not supported at all.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions,
or pull requests.**

Report them privately through GitHub Security Advisories:

👉 https://github.com/nest-extended/nest-extended/security/advisories/new

If you cannot use GitHub Security Advisories, email a maintainer at
`sahoosantanu92@gmail.com` with `[SECURITY]` in the subject line.

### What to include

To help us triage quickly, please include as much of the following as you can:

- The affected package(s) and version(s)
- The type of issue (e.g. command injection in a CLI generator, path traversal in a template
  writer, query injection through the FeathersJS-style query parser, unsafe defaults in a
  scaffolded `AuthModule`)
- Step-by-step reproduction instructions, ideally a minimal project or failing test
- Any proof-of-concept or exploit code
- The impact, and how an attacker might exploit it

### What to expect

- **Acknowledgement:** within 3 business days.
- **Initial assessment:** within 7 business days, including whether we accept the report and
  our severity assessment.
- **Progress updates:** at least every 7 days until the issue is resolved or closed.
- **Fix and disclosure:** accepted vulnerabilities are fixed in a patch release of every
  affected package. We publish a GitHub Security Advisory when the fix ships and credit the
  reporter unless you ask to stay anonymous.
- **If declined:** we will explain why we do not consider it a vulnerability (for example,
  issues that require an attacker to already control the developer's machine, or that live in
  an upstream dependency). Where the root cause is upstream (NestJS, Prisma, TypeORM,
  Mongoose, or another dependency), we will tell you and, where we can, help route the report
  to the right project.

Please give us a reasonable opportunity to release a fix before disclosing the issue
publicly.

## Scope

In scope:

- The published `@nest-extended/*` packages
- Code generated by `@nest-extended/cli` — including the scaffolded `AuthModule` and
  `UsersModule` — where the generated defaults are themselves insecure
- The build and release tooling in this repository

Out of scope:

- Vulnerabilities in dependencies with no NestExtended-specific exploit path — report those
  upstream (Dependabot already tracks dependency updates here)
- Issues in your own application code that merely uses these packages
- Findings that require an attacker to already have local code execution or write access to
  the project being scaffolded
